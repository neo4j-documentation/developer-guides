The https://modelcontextprotocol.io/introduction[Model Context Protocol (MCP)^] is the open standard for connecting AI assistants and agents with tools, data sources, and services.

Neo4j provides first-class MCP support - a https://neo4j.com/docs/mcp/current/mcp-for-aura/[hosted MCP server built into every Aura instance^], the https://github.com/neo4j/mcp[official Neo4j MCP server^] for any deployment, the https://neo4j.com/docs/aura/aura-agent/[Aura Agent service^] with MCP endpoints of its own, and integrations with all major https://neo4j.com/labs/genai-ecosystem/agent-frameworks/[agent frameworks^] and https://neo4j.com/labs/genai-ecosystem/agent-platforms/[agent platforms^].

== MCP - an Easy and Quick Way to Connect Agents to Databases

MCP is an easy and quick way to connect agents to databases: instead of hand-writing integrations, you configure an MCP server and the agent can immediately query your database.

The Neo4j MCP servers offer *query execution*, which allows the agent to push computation down into the database - pattern matching, traversals, aggregations, and complex analysis run where the data lives, and only the results are returned for the agent to process, summarize, or visualize.
For the agent to generate meaningful queries, it needs *schema understanding* - that's why the servers also expose schema introspection tools, so the agent can discover node labels, relationship types, and property keys before writing Cypher.

image::https://cdn-images-1.medium.com/max/1024/1*UnC-f-LmG5RB-wk3G16TgQ.png[]


A few things to keep in mind for database interactions over MCP:

* *Security and protection* - decide whether the server runs in read-only or read-write mode, and restrict which databases and users it can access. The read-only enforcement of `read-cypher` makes it safe to hand the server to an agent for analysis.
* *Data volumes* - you can't send millions of results to an LLM. Agents should use targeted queries, filtering, aggregation, sorting, and pagination (`LIMIT`) to return only what fits into the context window.

There are lot of ways how this can be useful from data analysis and visualization, to coding assistance. The same MCP server supports experimentation, prototyping, and production integration.

* designing a graph schema interactively, 
* generating data classes (e.g. Python models or TypeScript types) from the schema, 
* validating application queries, 
* generating and loading datasets, 
* generating validated unit tests for your Cypher queries

== MCP for Aura - Hosted MCP Server

MCP is now available in Neo4j Aura, so you don't have to run your own MCP server anymore.
https://neo4j.com/blog/genai/introducing-mcp-for-aura/[MCP for Aura^] is a *hosted MCP server built into every Aura instance* - each instance exposes its own MCP server URL that you connect to over HTTP from your MCP client, with OAuth-based authentication against your Aura account.

MCP for Aura is available for *Free, Professional, and Business Critical* tier instances (Virtual Dedicated Cloud support is coming later).

To get started:

. Enable *Tool authentication* for your organization in the https://console.neo4j.io[Aura Console^] (Security → Tool authentication with Aura user)
. Find your per-instance MCP server URL in the format `https://<INSTANCE_ID>.mcp-instances.neo4j.io` (copy it from the instance details panel via the Inspect menu)
. Add the URL as a remote MCP server in your MCP client (Claude, Cursor, VS Code, ChatGPT and others)

== Official MCP Server for Neo4j

The official https://github.com/neo4j/mcp[MCP Server for Neo4j^] reached 1.0 GA in November 2025 and is actively developed, with frequent releases (v1.6.0 in September 2026).
It is a local MCP server that is downloadable as a binary, installable via pip (`pip install neo4j-mcp-server`), and available as a Docker image, working with all types of Neo4j Deployments - Neo4j Aura, Self Managed, Docker, Neo4j Desktop, and Neo4j Sandbox.
The repository README and the documentation have installation instructions including the necessary environment variables for common MCP Hosts like Claude Desktop, VS Code and others.

The current version supports these tools:

- `get-schema` - introspect node labels, relationship types and property keys
- `read-cypher` - execute read-only Cypher queries, enforced via `EXPLAIN` and Neo4j's query-type classification
- `write-cypher` - execute write Cypher queries (disabled if the server runs in read-only mode)
- `list-gds-procedures` - list available GDS procedures for executing graph algorithms

Recent release highlights:

- *v1.6.0* (Sep 2026) - consistent `NEO4J_MCP_*` environment variables and concise CLI flags (replacing the older `NEO4J_URI`, `NEO4J_PASSWORD` etc. variables)
- *v1.5.x* (Mar-Jun 2026) - `/healthz` endpoint for liveness and readiness checks, improved OpenAI compatibility of the advertised tool schemas
- *v1.4.x* (Feb-Mar 2026) - custom auth header configuration, unauthenticated ping/tool listing options for health checks, multi-database preflight support
- *v1.2.0* (Jan 2026) - bearer token support and telemetry for HTTP mode, GDS tools over HTTP
- *v1.1.0* (Dec 2025) - HTTP transport mode with per-request authentication, CORS control and TLS/HTTPS support

== What is the Model Context Protocol

The https://modelcontextprotocol.io/introduction[Model Context Protocol] was introduced by Anthropic in November 2024 to ease the integration of LLM Assistants with tools providing access to data, services, APIs and local systems.

It has since become the de-facto standard for connecting AI agents with tools and data.
To ensure neutral, community-driven stewardship, Anthropic donated MCP to the https://aaif.io/[Agentic AI Foundation (AAIF)^], a https://aaif.io/projects/model-context-protocol[Linux Foundation project^] in which Neo4j is also a member.
The protocol is now developed by a https://modelcontextprotocol.io/community/governance[steering group of core maintainers^] together with a number of https://modelcontextprotocol.io/community/working-interest-groups[Working Groups (WGs) and Interest Groups (IGs)^] that drive the specification through Specification Enhancement Proposals (SEPs).

The MCP architecture consists of the *MCP Host* program which can be configured with a number of *MCP Servers* that provide capabilities like tools, resources, and prompts.

If you want to dive deeper, here is a https://neo4j.com/blog/developer/model-context-protocol/[comprehensive overview with explanations and examples with Neo4j^].

image::https://cdn.graphacademy.neo4j.com/assets/img/courses/banners/genai-mcp-neo4j-tools.png[width=800,link="https://graphacademy.neo4j.com/courses/genai-mcp-neo4j-tools/"]

Whenever a user (or agent) requests in an interaction some task that could be executed by or through using a MCP Server capability, the LLM will select the tool, extract parameters and invoke the tool through an *MCP Client* connected to the MCP Server.

image::https://dist.neo4j.com/wp-content/uploads/20250401141320/mcp-architecture-neo4j-e1743543257487.png[]

=== Recent Protocol Developments

The https://modelcontextprotocol.io/specification/2026-07-28[current specification revision (2026-07-28)^] made the protocol *stateless* and added more robust mechanisms for authentication and extensibility.
Major changes include:

- *Stateless protocol* - the `initialize`/`notifications/initialized` handshake and protocol-level sessions (`Mcp-Session-Id`) were removed; every request now carries its protocol version and client capabilities in `_meta`, and a new `server/discover` RPC lets clients probe supported versions and capabilities up-front.
- *Robust authorization* - building on OAuth 2.1 support from the 2025 revisions, the https://modelcontextprotocol.io/development/roadmap[roadmap^] prioritizes *agent identity and enterprise-ready security* (e.g. agent-card-based identity, delegation, and auditable access control) as a key area for the next revisions.
- *Multi Round-Trip Requests* - servers can return an `InputRequiredResult` asking the client for additional information, replacing server-initiated requests like `sampling/createMessage` and `elicitation/create`.
- *Feature lifecycle and deprecation policy* - features now have Active, Deprecated, and Removed states with a minimum twelve-month deprecation window, and tasks moved out of the core protocol into an official extension.
- *Agent Skills* - skills (reusable instruction packages that guide agents through multi-step tasks) are an emerging topic for MCP, complementing tools, resources, and prompts.
- *MCP Registry* - the official https://modelcontextprotocol.io/registry/about[MCP Registry^] (currently in preview) provides a centralized, DNS-verified metadata repository for publicly accessible MCP servers, backed by major ecosystem contributors such as Anthropic, GitHub, PulseMCP, and Microsoft - addressing the earlier discovery problem.

With the governance, working groups, and major providers in place, the earlier open questions around security, discovery, and trusted deployment are being addressed systematically through the SEP process.

=== MCP Servers

MCP Servers are providing an implementation of the MCP protocol (JSON-RPC) over different transports - standard-I/O or HTTP(S), with http based servers growing in relevance since OAuth 2.1 support was added to the specification.

To make servers discoverable, the official https://modelcontextprotocol.io/registry/about[MCP Registry^] (in preview) lets server creators publish metadata in a standardized `server.json` format (with DNS-verified namespaces like `io.github.user/server-name`), which MCP clients and aggregators can use to discover, install, and configure servers via a REST API.

They offer these capabilities:

* *tools* - tools can retrieve data or take action, they take parameters and return results or errors to the client
* *resources* - read only static or dynamic resources, like files, pages, schemas
* *prompts* - multi-step prompts with placeholders to guide user interactions with this service

=== MCP Clients/Hosts

An MCP Host (LLM application like Claude, Cursor or VS Code) can be configured with a number of MCP Servers.
When a server is activated, the host opens a connection to it, and whenever a user requests a task for which one of its capabilities can be used, the LLM extracts the parameters from the instruction and conversational context, selects the best tool, and sends a request - the response is integrated into the current context, used in the conversation, and can feed further MCP calls or generated artifacts like documents, images, and code.

Clients range from AI powered IDEs and developer tools (Cursor, Windsurf, VS Code, MCP Inspector, Cline) to end user tools (Claude Desktop, MSFT Copilot Studio, Google Agentspace, OpenAI ChatGPT connectors), agent frameworks (see <<#_mcp_with_agent_frameworks_and_agent_platforms,below>>), and the agents built into platforms like Aura.

A full, up-to-date list of MCP clients is maintained at https://modelcontextprotocol.info/docs/clients/[modelcontextprotocol.info/docs/clients/^].

== MCP with Agent Frameworks and Agent Platforms

Most Agent Frameworks support MCP servers as tools, and so also the Neo4j MCP servers - both the official https://github.com/neo4j/mcp[Neo4j MCP server^] and the hosted https://neo4j.com/docs/mcp/current/mcp-for-aura/[MCP for Aura^].

The Neo4j MCP server is the primary integration point across agent frameworks and platforms, exposing Cypher execution and schema inspection as standard tools that any MCP-compatible agent can call.
For frameworks that prefer direct integration, the Neo4j drivers and packages like `langchain-neo4j` and `llama-index-graph-stores-neo4j` provide native tool definitions and vector store support.

We have added a lot of integrations for agent frameworks and agent platforms using the Neo4j MCP server.
Detailed, step-by-step integration guides for each of them can be found in the https://neo4j.com/labs/genai-ecosystem/agent-frameworks/[Agent Frameworks^] and https://neo4j.com/labs/genai-ecosystem/agent-platforms/[Agent Platforms^] sections of the Neo4j Labs GenAI Ecosystem.

=== MCP-Neo4j-Memory

MCP came with an example knowledge graph implementation for storing memories, we upgraded that to use Neo4j as a real graph database.

The https://github.com/neo4j-contrib/mcp-neo4j/tree/main/servers/mcp-neo4j-memory[mcp-neo4j-memory Server^] stores and updates entities with observations and relationships between them in Neo4j and can search and retrieve subgraphs of relevance.

It also works for long conversations or plans that turn into more comprehensive eknowledge graphs.

It offers these tools and operations:

Querying

* `read_graph` load whole graph
* `search_nodes` by search string
* `find_nodes` by name

Updating

* `create_entities`, `delete_entities` - create memory entities
* `create_relations`, `delete_relations` - manage relationships
* `add_observations`, `delete_observations` - add observation statements to entities

=== MCP Neo4j Aura Manager

One interesting area for developers of using MCP servers is actually not the data side but infrastructure.
While developing applications, it is useful to spin up or manage database instances, or pause/resume from the comfort of your IDE.
Other infrastructure aspects could be migrations, cost overviews, inviting team members etc.

The https://github.com/neo4j-contrib/mcp-neo4j/tree/main/servers/mcp-neo4j-cloud-aura-api[mcp-neo4j-aura-manager^] provides access to the https://neo4j.com/docs/aura/platform/api/specification/[Neo4j Aura API^] for managing databases, tenants, projects.

When configured with client-id and client-secret the MCP server can access the Aura API on your behalf and offers the following tools as operations:

Instance Management

* `list_instances`
* `get_instance_details`, `get_instance_by_name`

* `create_instance`, `delete_instance`
* `update_instance_name`, `update_instance_memory`, `update_instance_vector_optimization`
* `pause_instance`, `resume_instance`

Tenant/Project Management

* `list_tenants`
* `get_tenant_details`

=== MCP-Neo4j-GDS

The Neo4j Graph Data Science Server (https://github.com/neo4j-contrib/gds-agent[GDS-Agent]) provides GDS algorithms as tools.

This allows users to ask questions that require nontrivial reasoning with graph algorithms.
An LLM equipped with the GDS agent will find and execute the correct algorithms with appropriate parameters.

An example where an LLM with GDS Agent is able to pick shortest path and Yen's algorithm (and with small k=3) to answer a question about travel planning for a map in the Neo4j database:

image::gds-agent-london-underground-example.png[]

It currently support a large set of GDS algorithms, including:

* `Centrality algorithms`: Article Rank, Articulation Points, Betweenness Centrality, Bridges, CELF, Closeness Centrality,
Degree Centrality, Eigenvector Centrality, PageRank, Harmonic Centrality, HITS
* `Path algorithms`: Dijkstra's Shortest Path, Delta Stepping Shortest Path, Dijsktra's Single Source Shortest Path,
A-Star, Yen's, Minimum Weight Spanning Tree, Minimum Weight k-Spanning Tree, Minimum Directed Steiner Tree, Prize Collecting Steiner Tree, All Pairs Shortest Path, Random Walk, BFS, DFS, Bellman-Ford Single Source Shortest Path, Longest Path
* `Community detection algorithms`: Conductance, HDBSCAN, K-Core Decomposition, K-1 Coloring, K-Means Clustering,
Label Propagation, Leiden, Local Clustering Coefficient, Louvain, Modularity Metric, Modularity Optimization, Strongly Connected Component, Triangle Count, Weakly Connected Component, Approximate Maximum K-Cut, Speaker-Listener Label Propagation
* `Similarity algorithms`: Node similarity, Filtered Node Similarity, K-Nearest Neighbors, Filtered K-Nearest Neighbors

For full documentation and instructions, please refer to the repository: https://github.com/neo4j-contrib/gds-agent

=== MCP-Sandbox

The Sandbox MCP Server (https://mcp.sandbox.neo4j.com/sse) server provides tools for managing https://sandbox.neo4j.com[Neo4j Sandboxes^] instances directly from your development environment. This server simplifies the development workflow by allowing you to programmatically control your sandboxes.
Its GitHub repository can be found here: https://github.com/neo4j-contrib/sandbox-mcp-server[sandbox-mcp-server^]

A key feature of this MCP server is the ability to not only manage the lifecycle of sandboxes (creating, terminating, extending) but also to directly interact with the data inside them. You can retrieve the database schema and execute both read and write Cypher queries on any of your running sandbox instances. This is particularly useful for rapid prototyping, testing, and data exploration without leaving your IDE.

Instance & User Management:

* `start_new_sandbox` - Creates a new sandbox instance for a specific use case.
* `list_sandboxes_for_user` - Lists all active sandboxes for the user.
* `terminate_sandbox` - Deletes a sandbox instance.
* `get_sandbox_connection_details` - Retrieves connection details for a sandbox.
* `extend_sandbox_lifetime` - Extends the lifetime of a sandbox.

Data Interaction:

* `get_schema` - Fetches the graph schema from a sandbox.
* `read_query` - Executes a read-only Cypher query.
* `write_query` - Executes a write Cypher query.

Backup & Aura Upload:

* `request_sandbox_backup` - Requests a backup for a sandbox.
* `list_sandbox_backups` - Lists available backups for a sandbox.
* `get_backup_result` - Retrieves the result of a backup task.
* `get_sandbox_backup_download_url` - Gets a download URL for a backup file.
* `upload_sandbox_to_aura` - Uploads a sandbox backup to an Aura instance.
* `get_aura_upload_result` - Retrieves the result of an Aura upload task.

== Google MCP Toolbox

https://googleapis.github.io/genai-toolbox/getting-started/mcp_quickstart/[Google's MCP Toolbox for Database^] is an https://github.com/googleapis/genai-toolbox[open source tool^] to integrate a variety of databases as sources for agentic systems. 

Individual parameterized queries can be defined as tools and made available to agent frameworks.
Toolbox takes care of database connection management, authentication, result processing and error handling.

Toolbox integrates as an MCP Server but also directly with LangChain and LlamaIndex.

You can deploy MCP toolbox to Cloud Run or Kubernetes or run it locally on your system.

The Neo4j Integration was added early in Dec 2024, and provides

* https://googleapis.github.io/genai-toolbox/resources/sources/neo4j/[Neo4j Source^]
* https://googleapis.github.io/genai-toolbox/resources/tools/neo4j-cypher/[Neo4j Cypher Tools^]
* https://googleapis.github.io/genai-toolbox/resources/tools/neo4j/neo4j-execute-cypher/[Neo4j Execute Cypher^]
* https://googleapis.github.io/genai-toolbox/resources/tools/neo4j/neo4j-schema/[Neo4j Schema^]
